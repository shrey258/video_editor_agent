# Video Editor Agent

Upload a short video, then trim it and change its speed with natural language (Gemini) or by hand on a timeline, and export an mp4. There are two apps:

- `backend/`: FastAPI + ffmpeg + Gemini REST.
- `frontend/`: Next.js 15 + Zustand + Tailwind.

## Read before working

1. `INDEX.md` maps every file to what it owns. Find the file there instead of grepping blind.
2. `DESIGN.md` covers tokens, components and variants. Read it before editing any `.tsx`.
3. `graphify-out/GRAPH_REPORT.md` shows the knowledge graph: god nodes, communities, cross-file links. For "what calls X / what breaks if I change Y", run `graphify query "<question>"` first.

## Commands

```bash
mprocs                                                   # both apps: backend :8000, frontend :3000
cd backend && .venv/bin/uvicorn app.main:app --reload --port 8000
cd backend && .venv/bin/pytest -q                        # backend tests
cd frontend && npm run dev | npm run test | npm run lint | npm run build
```

CI (`.github/workflows/ci.yml`) runs exactly `pytest -q`, `npm run lint`, `npm run test` and `npm run build`. Before calling a change done, run the ones for the side you touched.

## Architecture in five lines

- The frontend never calls the backend directly. It calls `/api/*`, and `next.config.ts` rewrites that to `NEXT_PUBLIC_API_BASE` (default `http://127.0.0.1:8000`). Never hardcode `:8000` in a component.
- All backend `fetch` calls live in `components/editor/inspector.tsx`. All editor state (playback, `trimRanges`, `speedRanges`) lives in `components/editor/video-store.ts`. Components read it through `useVideo()`.
- Every route is in `backend/app/main.py`. Every ffmpeg/ffprobe subprocess is in `backend/app/video_tools.py`. Every Gemini call is in `backend/app/gemini_agent.py`. Keep those boundaries: no subprocess calls in `main.py`.
- `backend/app/schemas.py` is the API contract. When you change a model, update the matching TypeScript type in `inspector.tsx` in the same change.
- Media is written to `MEDIA_ROOT` (`media/uploads`, `media/outputs`, `media/sprites`) and served back at `/media/*`.

## Gotchas

- **Videos over 10s are rejected.** `MAX_VIDEO_DURATION_SEC` defaults to `10`. If an upload fails, check this before debugging anything else.
- **Gemini is optional.** With no `GEMINI_API_KEY`, `parse_intent` and `suggest_cuts_from_sprites` fall back to regex/heuristics and still return 200 (suggest-cuts marks it `model: "fallback"`, while `parse_intent` only logs `PARSE_INTENT_FALLBACK_RESPONSE`). A "working" AI response may not be AI at all. The model name (`gemini-2.0-flash`) is hardcoded in `gemini_agent.py`.
- **Python version drift.** The local `backend/.venv` is Python 3.9 (Xcode's). CI and Docker use 3.11. Code must run on 3.9 until the venv is rebuilt: no `match`, and every module keeps `from __future__ import annotations` as its first line (that's what makes the existing `int | None` hints legal on 3.9).
- **ffmpeg must be on PATH.** Backend tests monkeypatch ffmpeg and Gemini (`tests/test_api.py`), so a green test run does not prove ffmpeg works. Hit the real endpoint for that.
- `timeline.tsx` (~1000 lines) and `inspector.tsx` (~700 lines) are large. Make local edits. Don't reformat or reorder them.
- Timeline keyboard shortcuts (`a`, `+`, `-`, `t`, Backspace/Delete) are one `keydown` listener in `timeline.tsx`. Any new shortcut must go there and skip events from inputs and textareas.
- `components/editor/toolbar.tsx` is an empty stub. `.codex/environments/environment.toml` is autogenerated.

## Never

- Read or print `backend/.env` or `frontend/.env.local`. They hold real keys. Use the `.env.example` files.
- Commit anything under `media/`. It holds real user videos.
- Add a dependency for something the existing stack does (`cn()`, Radix, zustand, lucide, httpx).
